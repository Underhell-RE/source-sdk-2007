# Система расчленений: наш порт vs. оригинал

Сверка `game/server/underhell/uh_ai.cpp` с декомпилом
`Underhell/bin/diaphora/servero_diaphora.dll.c` (Diaphora), референс — та самая
`sub_10031BF0`, которая в `ARENA_CURRENT_STATE.md` числится непортированной:

> Full `CNPC_CombineS` `sub_10031BF0` behavior is not ported.

Функция найдена и прочитана. В декомпиле она подписана как
`CAI_BaseNPC::StartTask(CAI_BaseNPC *this, const Task_t *pTask)` — это
**ошибочная сигнатура Hex-Rays**: реально это обработчик попадания, где
`pTask` — это `hitgroup` (значения 1/2/4/6/8 в switch), а `v85` —
`CTakeDamageInfo` (по `v85+52` лежит урон, по `v85+4..12` — вектор силы).
Ориентироваться на имя не надо, надо на тело.

Общий вывод: **структура портирована узнаваемо правильно, но численная модель
здоровья частей тела принципиально другая, и пороги вдвое завышены.**

---

## 🔴 Расхождение 1 — модель здоровья: накопление урона vs. вычитание HP

Это главное. Мы копим урон вверх до порога, оригинал вычитает урон из
пер-частевого запаса HP вниз до нуля.

**Оригинал** — инициализация в конструкторе (`@463685-463693`):

```c
*(_DWORD *)(this + 1708) = uh_helmethealth;        // 30      каска
*(_DWORD *)(this + 1716) = uh_headhealth / 2;      // 21/2 = 10   голова
*(_DWORD *)(this + 1720) = uh_gibhealth  / 4;      // 80/4 = 20   рука L
*(_DWORD *)(this + 1724) = uh_gibhealth  / 4;      // 80/4 = 20   рука R
*(_DWORD *)(this + 1728) = uh_gibhealth  / 2;      // 80/2 = 40   нога L
*(_DWORD *)(this + 1732) = uh_gibhealth  / 2;      // 80/2 = 40   нога R
```

Вычитание при попадании (`@130928`, hitgroup 4):

```c
*((_DWORD *)this + 430) = (int)((double)*((int *)this + 430) - *(float *)(v85 + 52));
```

и гейт срабатывания — `if ( *((int *)this + 430) > 0 ) return;`
(`@130936`, `@130975`, `@131020`). То есть: **пока запас части > 0, отрыва нет;
как только ушёл в ноль/минус — часть отрывается.** Аналогично голова через
поле 429 (`@130648-130649`).

**У нас** (`uh_ai.cpp:648-681`):

```cpp
m_flGibDamage[idx] += flDamage;

float flThreshold = 0.0f;
if ( iHitGroup == HITGROUP_HEAD )
    flThreshold = uh_headhealth.GetFloat();          // 21   ← оригинал 21/2 = 10
else if ( LEFTARM || RIGHTARM )
    flThreshold = uh_gibhealth.GetFloat() * 0.5f;    // 40   ← оригинал 80/4 = 20
else
    flThreshold = uh_gibhealth.GetFloat();           // 80   ← оригинал 80/2 = 40

if ( m_flGibDamage[idx] < flThreshold )
    return false;
```

Сравнение фактических значений при дефолтных конварах:

| часть | оригинал | у нас | во сколько раз тяжелее |
|---|---|---|---|
| голова | 10 | 21 | **2.1x** |
| рука (кажд.) | 20 | 40 | **2x** |
| нога (кажд.) | 40 | 80 | **2x** |
| каска | 30 | 30 | ✅ 1x |

**Расчленить NPC у нас ровно вдвое дороже, чем в оригинале.** Комментарий
`// arms = 50% of legs` угадал *соотношение* рук к ногам (1:2 — верно), но
потерял общий делитель: у оригинала руки это `/4`, а не `/2` от `uh_gibhealth`.

Кроме того накопительная модель отличается от вычитающей поведенчески:
- у оригинала запас **сохраняется в поле энтити** и переживает
  сейв/лоад (это часть состояния NPC), а `m_flGibDamage[]` надо проверить
  на предмет `DEFINE_ARRAY` в датадеске;
- «вылечить» часть тела оригинал может простым присваиванием запаса,
  у нас пришлось бы обнулять накопитель;
- при `uh_gibhealth 0` оригинал отрывает всё с первого попадания
  (`0/4 = 0`, `0 > 0` ложно), у нас `0 >= 0` — тоже сработает, но при
  отрицательных значениях конвара поведение разойдётся.

**Рекомендация:** перейти на вычитающую модель с полями
`m_iHeadHealth/m_iArmHealth[2]/m_iLegHealth[2]/m_iHelmetHealth`,
инициализируемыми в `Spawn()` как `uh_headhealth/2`, `uh_gibhealth/4`,
`uh_gibhealth/2`, `uh_helmethealth`.

## 🔴 Расхождение 2 — гейт «живой NPC не расчленяется» инвертирован

**У нас** (`uh_ai.cpp:666`):

```cpp
// Dead NPCs gib freely; the threshold only gates living NPCs.
if ( IsAlive() )
{
    ... накопление и проверка порога ...
}
UH_GibBodyPart( ... );   // труп — отрываем сразу, без порога
```

То есть: труп расчленяется **с одного попадания**, живой — по порогу.

**Оригинал делает наоборот.** Запас HP части вычитается и проверяется
**всегда**, независимо от того, жив NPC или мёртв — в `sub_10031BF0` нет
никакой проверки `IsAlive()` вокруг гейта `*((int *)this + 430) > 0`.
Труп в оригинале надо так же «прострелить» на 20/40 единиц урона, чтобы
оторвать конечность. Именно поэтому расстрел трупа в оригинале ощущается
как работа, а не как мгновенная разборка.

Единственная проверка «живости» рядом — это флаг `*((_BYTE *)this + 1713)`
в самом начале функции (`@130572`):

```c
if ( !*((_BYTE *)this + 1713) )
    return;
```

Он ставится в 1 в конструкторе (`@463688`) — это флаг «расчленение
разрешено для этого NPC», а не «жив». Похоже, именно он соответствует нашему
`m_bUhGibEnabled`/аналогу — стоит проверить, что мы его не путаем с `IsAlive()`.

## 🟡 Расхождение 3 — счётчик оторванных конечностей и «инвалидность»

Оригинал ведёт **счётчик состояния рук** через bodygroup-значение и по
достижении порога снимает флаг `*((_BYTE *)this + 1712)`:

```c
// вариант с шагом 2 (@130947-130952):
*(...)(this) = v40 + 2;
if ( v40 + 2 > 5 )
    *((_BYTE *)this + 1712) = 0;

// вариант с шагом 1 (@130984-130990):
*(...)(this) = v48 + 1;
if ( v48 == 2 )
    *((_BYTE *)this + 1712) = 0;
```

Байт 1712 — это, судя по всему, «NPC ещё может держать оружие / стрелять».
Когда обе руки оторваны, он гасится. У нас в `UH_GibBodyPart` **ничего
подобного нет** — NPC с двумя оторванными руками продолжает целиться и
стрелять из воздуха. Это заметный визуальный баг.

Рядом же оригинал разбирает оружие из рук:

```c
if ( *((int *)this + 55) > 0 )          // есть активное оружие
{
    v41 = *((_DWORD *)this + 593);
    if ( v41 != 36 && v41 != 34 && v41 != 35 )   // не эти три активности
    {
        *((_DWORD *)this + 637) &= ~8u;          // снять capability
        goto LABEL_86;                            // и просто спавнить гиб
    }
    v86 = 0;
    sub_1002AB00((_DWORD *)this + 55, &v86);      // иначе — выбросить оружие
}
*((_DWORD *)this + 435) |= 2u;                    // выставить флаг
```

То есть решение «уронить оружие или только снять способность» зависит от
текущей активности (`36/34/35`). У нас этой развилки нет вообще.

## 🟡 Расхождение 4 — шаг bodygroup 1 или 2 зависит от семейства модели

В оригинале в `case 4u` (рука) стоит **switch по `*((_DWORD *)this + 202)`**
— это идентификатор семейства модели/NPC:

```c
v39 = *((_DWORD *)this + 202);
if ( v39 == 2 )            goto LABEL_104;   // ветка "шаг 1"
if ( v39 != 1 ) {
    if ( v39 != 6 && v39 != 8 ) { ... }      // ветка "шаг 2"
    LABEL_104: ...                            // ветка "шаг 1"
}
```

- ветка «шаг 2»: `bodygroup += 2`, порог `> 5`, гейт `arm > 0`
- ветка «шаг 1»: `bodygroup += 1`, порог `== 2`, гейт `bodygroup % 2`

`ARENA_CURRENT_STATE.md` это частично поймал:

> - regular combine soldier: authored `0/2/4/6` arm states;
> - four-state variants: `0/1/2/3` states.

Соотношение угадано верно, но привязка у нас сделана к **имени модели**
(`UH_RemoveBodygroupSide` + эвристики по строке), а в оригинале — к
**числовому полю 202**, которое выставляется при спавне по типу NPC.
Значения ветвления: `1`, `2`, `6`, `8` — и они же используются в
голове/каске (`*((_DWORD *)this + 202) == 1` @130588,
`== 8` @131074, `@133311`). Это не имя модели, это enum варианта.
Пока мы парсим строки моделей, поведение будет расходиться на любом
NPC, чьё имя модели не совпало с нашим списком.

## Итоговая оценка похожести

| Слой | Похожесть |
|---|---|
| Визуал/эффекты (звуки, партиклы, декали, аттачменты) | **~95%** — почти 1:1 |
| Создание и физика гиба (sub-ragdoll, скин, перчатки) | **~90%** — верный механизм |
| Численная модель здоровья частей | **~40%** — другая модель, пороги 2x |
| Гейт «жив/мёртв» | **инвертирован** |
| Последствия для NPC (оружие, стрельба без рук) | **~10%** — почти нет |
| Ветвление по семейству модели | **~50%** — по строке вместо enum-поля |

То есть: **выглядит правильно, играется иначе.** Куски мяса, кровь и звуки
на месте и в нужных точках; а вот сколько надо стрелять, чтобы их получить,
и что после этого делает NPC — расходится существенно.

## Приоритеты доработки

1. **Пороги**: `uh_headhealth/2`, `uh_gibhealth/4` (руки), `uh_gibhealth/2` (ноги).
   Однострочная правка, сразу убирает двукратную разницу.
2. **Убрать `if ( IsAlive() )`** вокруг гейта — трупы должны требовать
   столько же урона, сколько живые.
3. **Перейти на вычитающие HP-поля** вместо накопителей (совместимость с
   сейвами и с возможным «лечением» частей).
4. **Флаг 1712** — гасить возможность стрелять при потере рук + разбор
   развилки с активностями 34/35/36.
5. **Поле 202** — ввести числовой идентификатор семейства NPC вместо
   эвристик по имени модели.
6. Мелочь: `"Player.HeadShot"` → `"Player.Headshot"`.
